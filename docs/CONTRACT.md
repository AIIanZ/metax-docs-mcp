# Implementation contract v1
Python >=3.11; package src/metax_docs_mcp. Official MCP Python SDK FastMCP; SQLite offline index.

models.py (core owner): dataclass Document(id: str, source: str, title: str, url: str, text: str, version: str = "", repository: str = "", path: str = "", revision: str = "", fetched_at: str = "", metadata: dict = field(default_factory=dict)). source is official or github. IDs stable by canonical source URL/path plus version where applicable. Core may add defaults only.
store.py (core owner): Store(db_path); upsert(doc: Document)->bool (true if changed); search(query, source=None, repository=None, version=None, limit=10)->list[dict]; get_document(document_id, offset=0, limit=12000)->dict|None; get_section(document_id, section)->dict|None; list_sources()->dict; close(). Search hits contain id,title,url,source,version,repository,revision,snippet and score; include provenance/fetched_at in read responses. Chunk sections internally for retrieval. Chinese + Latin technical token search required. Bound all sizes. Store initializes own schema.

sources.py (ingestion owner): sync_sources(store, config: dict, source: str = "all")->dict. Config contains official: {seeds: [url], max_pages: 100, discover: true}; github: {organization: "MetaX-MACA", repositories: [name], max_files_per_repo: 100, include_code: false}; http: {timeout: 20, retries: 2}. Optional GITHUB_TOKEN environment. Return counts discovered/indexed/unchanged/failed, errors and truncation/partial info. Public HTTPS allowlist only; bounded crawling; preserve sections/code; record exact commit for GitHub; no credentials in logs. May add supporting modules. No implicit unbounded full-organization crawling; empty repositories should discover bounded org repos or explain action required. Official live discovery findings to follow. Keep dependencies httpx, beautifulsoup4, markdownify available.

cli.py/server.py (interface owner): argparse CLI --db PATH then sync --config PATH [--source official|github|all], search QUERY [--source...] [--limit N], get ID [--offset N --limit N], section ID SECTION, sources, opdev [TOPIC] [--limit N], serve. JSON output; failures nonzero; log stderr only. MCP tools search_metax_docs(query,source=None,repository=None,version=None,limit=10), get_metax_document(document_id,offset=0,limit=12000), get_metax_section(document_id,section), list_metax_sources(), get_operator_guide(topic=None,limit=60). Read-only local MCP, no network/ingest tools. Env METAX_DOCS_DB default ~/.cache/metax-docs-mcp/index.sqlite3. Use FastMCP and stdio. pyproject dependencies mcp>=1.12,<2 httpx beautifulsoup4 markdownify; pytest dev; console script metax-docs-mcp.

opdev.py (operator guide owner): curated operator-development map rendered from code (`TOPICS`), so the Markdown view (`docs/OPERATOR_DEV.md`) and the MCP/CLI answers cannot drift. Each `OperatorTopic` has a slug, stage, summary, ordered steps and `OpReference` entries. A reference names its source and, depending on it, an official manual title (+ optional section) or a repository with an exact path / path prefix. References never embed commit SHAs: they are resolved at query time by `Store.find_documents`, which matches provenance exactly (case-insensitive Unicode substring for titles) and returns metadata only. Unresolved references are reported as `missing_references` rather than dropped, and unconditional validation (`validate_topics`) plus the refresh-time gate keep the map honest.

## Scope extension
`source=docker` is also supported by Store, CLI filters and sync dispatch. `docker_source.sync_docker(store,config,fetcher,stats,*,max_document_chars)` ingests the public official image catalog, without executing pull commands. `all` synchronizes only source sections present in config.

## Programming and framework coverage (2026-09-30)
`official.series: [name]` optionally filters catalog entries by exact series name and reports missing names. Child pages inherit catalog version metadata. `github.transport: api|archive` defaults to `api` for compatibility; the shipped config uses `archive`. `github.exclude_globs: [pattern]` filters before the file count bound. `github.max_archive_bytes` defaults to 128 MiB and is capped at 256 MiB. Archive ingestion is limited to 1 GiB expanded bytes, 100,000 members, and 8 MiB per selected file. It does not extract paths or follow links and verifies blob hashes against the pinned commit tree. Archive requests use an unauthenticated client restricted to codeload.github.com. The only explicitly allowed external repository is tile-ai/tilelang-metax. GitHub metadata adds content_kind and text_truncated; code text preserves its original whitespace and uses the file path as title. The MCP interface remains read-only with the same four tool signatures.

`github.repository_refs: {owner/name: ref}` selects one explicit branch/tag/commit per repository, otherwise the repository default branch is used. The configured ref is returned as version/metadata.branch and resolved to a fixed commit. File count is capped at 10,000. Stable repository/path IDs intentionally represent one active snapshot; switching refs requires a fresh database to avoid retaining files absent from the new branch.

## Operator development coverage (2026-10-14)
`github.repository_exclude_globs: {owner/name: [pattern]}` adds repository-scoped exclusions on top of the global `github.exclude_globs`; patterns are matched against the repository-relative path with `fnmatch` semantics found in the other exclusions. It exists because vendored copies (a bundled `mctlass`, upstream `third_party/amd`/`nvidia`/`json`) would otherwise be indexed several times over; a repo-scoped pattern can drop those duplicates without removing the same directory names from repositories that are already covered. Store gains `find_documents(source, repository, path, path_prefix, title, limit)`, a non-ranked provenance lookup that returns metadata only (no body text) and orders title matches by exact-title-first. The MCP surface stays read-only and gains one tool, `get_operator_guide(topic=None, limit=60)`: with no topic it returns the topic catalogue, with a slug it returns the topic plus resolved documents (`read_order`) and `missing_references`. `scripts/verify_expanded.py` now fails when any topic reference does not resolve, so a stale curated entry blocks publication instead of silently degrading the guide.

### Refresh orchestration (2026-10-14)
`scripts/refresh_index.py` keeps owning staging, integrity, stdio verification, backup and atomic publication, and now drives the crawl itself: non-GitHub sources run once, GitHub runs in batches of `METAX_REFRESH_GITHUB_BATCH` (default 4) repositories written into the same staging database, and a batch whose failures are all GitHub API rate limits is retried after sleeping until the published reset time (bounded by `MAX_RATE_LIMIT_WAITS`, and a mixed or non-rate-limit failure is never retried). It also tolerates SGLang release discovery failing, keeping the configured ref instead of aborting the run. Per-batch reports are kept as `sync-*.json` next to the merged `sync.json`, so a run can be audited batch by batch.
